# Planning v2 implementation plan (Colorado)

Status: approved direction, not started. Prepared 2026-10-09.
Branch: `claude/planning-v2`, created from `origin/main` (`5ef3d9c`). The earlier pilot remains on `codex/planning-cost-clarity` as a read-only reference; nothing from it is merged wholesale.

## 1. Outcome

A planner builds a Colorado corridor cost estimate the way the Lucerne Improvement Alternatives page works: choose a template, enter a few corridor facts, switch elements on and off, adjust any dollar amount, and compare named alternatives against a budget. Every element starts from a calculated 2026 planning cost derived from the app's Colorado bid data. One number is foregrounded with a secondary range. When the planner is done, the estimate can be printed, exported as CSV, shared as JSON, and later converted into an ordinary engineer Project.

The tool does not show review states, evidence filters, unresolved-decision tracking, frozen snapshots, or caveat blocks in the planner flow.

## 3. Cost model

For each selected element:

```
direct      = Σ (quantity from inputs × unit price from the price table)      // item-mapped elements
            or  count/length × assembly unit cost                              // multi-item elements
all-in      = direct × (1 + minor-items factor[base type])
                     × (1 + traffic-control factor[base type])
                     × (1 + mobilization factor[base type])
element $   = planner override if present, otherwise all-in
```

Summary:

```
Construction       = Σ element $
Contingency        = Construction × stage contingency %
Design engineering = (Construction + Contingency) × design %
Construction eng.  = (Construction + Contingency) × CE %
Right-of-way, Utility relocation = planner dollar entries (default $0, shown as "Not included" when $0)
Total              = sum of the above
Range              = Total × stage band (low %, high %)
Budget remaining   = Budget − Total (only when a budget is entered)
```

- The factors are keyed by base treatment (mill & overlay, reconstruction, path, elements-only). Phase 1 measures them; the earlier exploratory analysis found a median whole-contract to milling+asphalt ratio of 1.69 for resurfacing-type CDOT contracts, with mobilization and traffic control each about 8%.
- Default stage values are proposals for Stop 1: **Concept** contingency 30%, range −25%/+50%; **Planning study** contingency 25%, range −20%/+30%. Design 10% and construction engineering 10% remain editable project-level percentages.
- Price basis: NHCCI currently ends at 2025 Q4. Default treatment is adjustment to the latest loaded quarter plus a library-level escalation factor to 2026 (default value decided at Stop 1). The label states the actual basis.
- Rounding: full precision internally; element amounts display to the nearest $1,000, totals to the nearest $10,000, unit prices to two decimals.

## 4. Prototype element library (Colorado)

| Group | Selection | Elements | Driving inputs |
|---|---|---|---|
| Base treatment | Select one | Mill & overlay; Full-depth reconstruction (existing surface asphalt/concrete); New multi-use path; None | Length, width, existing surface |
| Corridor elements | Add any | Sidewalk; Curb & gutter; Bike lanes (striping and symbols); Buffered bike lane; Corridor lighting; Landscaping / tree lawn; Storm drainage allowance | Length, sides, width |
| Spot elements | Add any | ADA curb ramps (default intersections × 4); Marked crosswalk; Enhanced crossing (RRFB); New or rebuilt signal; Median refuge island; Bus stop upgrade | Counts |
| Other costs | Dollar entry | Right-of-way; Utility relocation | Amount |

Templates (presets of the above): Mill & overlay; Full reconstruction; Complete street; Sidewalk gap; Multi-use path; Intersection safety.

### Library file shape (illustrative)

`data/planning/co_element_library.json` (hand-edited) references `public/data/states/co/planning_prices.json` (generated):

```json
{
  "id": "sidewalk",
  "group": "corridor",
  "label": "Sidewalk",
  "inputs": [
    { "key": "lengthMiles", "inherit": "project.lengthMiles" },
    { "key": "sides", "default": 2, "options": [1, 2] },
    { "key": "widthFt", "default": 6 }
  ],
  "components": [
    { "item": "co_cdot_608-00000", "rule": { "kind": "area", "unit": "SY" } },
    { "item": "co_cdot_202-00200", "rule": { "kind": "area", "unit": "SY" }, "when": "existingSidewalk" }
  ],
  "note": "New 6 ft concrete sidewalk; removal of existing walk where present."
}
```

Multi-item elements (signal, RRFB, lighting, refuge island, bus stop, landscaping, drainage) use `"assembly": { "unit": "EACH" | "MILE", "cost": <2026 $>, "basis": "<derivation>" }` instead of item components.

## 6. Agent operating model

The primary session is an **Opus** orchestrator. It owns the plan, shared types, integration, review of all delegated work, final checks, and all Git operations.

| Model | Use for |
|---|---|
| Opus subagent | Cost-method derivation, assembly costs, element-to-Project mapping, UI layout design, adversarial review |
| Sonnet subagent | UI implementation and wiring, generator script implementation, tests from a written specification |
| Haiku subagent | High-volume bounded work: item inventories per element, fixture tables, regression runs, mechanical comparisons |

Rules (adapted from `AGENTS.md`):

- At most three concurrent subagents. Each assignment states objective, exclusive file ownership, deliverable, verification method, and restrictions.
- Subagents do not commit, push, create pull requests, spawn further agents, or edit files they do not own.
- The orchestrator inspects every edit and every Haiku/Sonnet numeric output before using it.
- Stop points (section 8) are session boundaries for user review and context management. Before each stop, the orchestrator updates the completion log, commits, and pushes.

| 5d. Project compatibility regression sweep | Haiku | tests only |

Mapping defaults for 5a to confirm or revise:

- Item-mapped components become catalog lines with exact `agencyItemId`, calculated quantity, and price-table unit cost.
- Assembly elements become custom Construction lines (quantity and unit cost).
- An overridden element becomes one custom line at the override amount, because its items no longer reconcile.
- Minor items, traffic control, and mobilization become three custom Construction lines.
- Contingency becomes the Project's native contingency percentage.
- Engineering, right-of-way, and utility amounts become Other Costs lines.
- The Project total equals the Planning total within $1.
- No intents, decisions, frozen lines, or priced-subtotal mode.

**Exit:** a created Project opens in the normal item table, reconciles to Planning, and existing Projects, backups, and CSV exports behave as before.
